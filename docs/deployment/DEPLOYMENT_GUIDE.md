# Audi MMI 3G+ Manual SD-Card Deployment Guide

This guide defines the standard manual deployment workflow for applying candidate update packages built with Audi MMI Studio to Audi Multi Media Interface (MMI 3G+ / HN+ / HN+R) hardware [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L830].

---

## 1. Deployment Trust Boundary & Safety Model

Audi MMI Studio maintains an immutable deployment trust boundary [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L945]:
- The software produces verified FAT32 SD media images and build attestation manifests, but never interfaces with vehicle CAN/MOST buses or automates vehicle flashing [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L73].
- Flashing head units involves inherent hardware risks; all deployment procedures are exclusively manual and performed at the operator's sole discretion [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L945].
- The phrase "SAFE TO INSTALL" is permanently banned across all tool outputs and documentation (§14.9) [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L913].
- Every build generated by Audi MMI Studio is formally classified as `BUILD READY — DEPLOYMENT NOT VERIFIED` until confirmed on physical test bench hardware [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L978].

---

## 2. SD Card Hardware & Filesystem Preparation

MMI 3G+ QNX bootloaders require strict FAT32 layout geometry [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L760]:
- **Card Specification**: Use a high-quality SDHC card (Class 10 / UHS-I) with a maximum capacity of 32 GB [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L760]. Cards larger than 32 GB formatted as exFAT or NTFS are rejected by the MMI bootloader [INF:HIGH basis: observed QNX devb-eide driver constraints].
- **Partitioning**: Partition table must be MBR (Master Boot Record); GPT partitions are unreadable by MMI 3G+ [INF:HIGH basis: MBR partition scheme observed in OEM update media].
- **Cluster Geometry**: Format the partition with FAT32 using exactly 32 KiB (64 sectors per cluster) allocation units [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L760].
- **Volume Label**: The volume label must be uppercase ASCII and maximum 11 characters, such as `MMI3G_NAV` or `MMI3G_UPD` [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L760].
- **Formatting Command (macOS/Linux)**:
  ```bash
  sudo newfs_msdos -F 32 -c 64 -v MMI3G_UPD /dev/diskXs1
  ```
- **Windows Formatting**: Use the official SD Association SD Card Formatter or `fat32format.exe` with a 32,768 cluster size [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L760].

## 3. Deployment File Structure & Volume Layout

Deployable packages must be copied directly to the root of the SD card [EV:tree@originals/HN+R_EU_AU_K0942_4_[8R0906961FB]]:
- The root of SD Slot 1 must contain `metainfo2.txt` accompanied by module payload directories [EV:tree@originals/HN+R_EU_AU_K0942_4_[8R0906961FB]/metainfo2.txt].
- Large navigation updates spanning multiple volumes must be split into volume directories (`SD1`, `SD2`) generated via `mmi-studio-cli build-media` [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L763].
- Hidden macOS dotfiles (`._*`, `.DS_Store`, `.Trashes`) must be stripped before insertion, as extra directory entries can cause parsing aborts during QNX file indexing [INF:HIGH basis: standard QNX FAT directory walking behavior]:
  ```bash
  dot_clean /Volumes/MMI3G_UPD
  ```

## 4. Pre-Deployment Vehicle Readiness Checklist

Before initiating any head-unit update, verify all operational prerequisites [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L830]:
- **Battery Support**: Connect a dedicated automotive battery maintainer delivering at least 12.5V and 25A continuous current [INF:HIGH basis: update interruption due to battery discharge causes bootloader recovery lockouts].
- **Auxiliary Systems**: Turn off climate control, headlights, seat heaters, and interior lights to minimize electrical noise [INF:MEDIUM basis: common automotive flash update protocols].
- **Key Ignition**: Turn ignition ON (engine OFF); keep ignition continuous throughout the installation [INF:HIGH basis: MMI sleep timer triggers if ignition turns off].
- **Media Removal**: Eject any existing CDs, DVDs, and secondary SD cards from Slot 2 to avoid volume contention [INF:MEDIUM basis: MMI boot priority checks].

## 5. Standard Engineering Menu Update Procedure

The MMI 3G+ software update is invoked through the Red Engineering Menu (REM) [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L830]:
1. **Enter Red Engineering Menu**: Press and hold `CAR` + `BACK` simultaneously for approximately 5 seconds until the red screen displays [INF:HIGH basis: established MMI 3G+ diagnostic button sequence].
2. **Insert Media**: Insert the prepared deployment SD card into `SD Slot 1` (left slot) [EV:tree@originals/HN+R_EU_AU_K0942_4_[8R0906961FB]].
3. **Select Update**: Scroll to and select `Update`, then choose `SD 1` as the source medium [INF:HIGH basis: OEM update navigation flow].
4. **Choose Update Mode**:
   - For complete OEM updates: select `Standard` [INF:HIGH basis: metainfo2 section matching].
   - For custom asset replacements: select `User Defined` (enabled via Green Engineering Menu `swdl / user defined`) to cherry-pick modified modules without re-flashing intact packages [INF:HIGH basis: QNX swdl user-defined mode].
5. **Start Download**: Scroll to the bottom of the module selection list and select `Start download` [INF:HIGH basis: QNX update state machine].
6. **Reboot & Confirmation**: The system will execute update scripts, flash updated modules, and automatically trigger a software reboot [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L765].
7. **Version Verification**: Re-enter `Setup MMI` -> `Version information` to verify that active module versions match the expected release string [EV:tree@originals/HN+R_EU_AU_K0942_4_[8R0906961FB]/metainfo2.txt].
