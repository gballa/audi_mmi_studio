# Audi MMI Studio Release Packaging & Distribution Guide

This document establishes the release packaging, distribution manifest, and Software Bill of Materials (SBOM) for the Audi MMI Studio Workstation [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L4].

## 1. Release Identification and Architecture

Audi MMI Studio is packaged as a dual-interface offline workstation comprising headless CLI automation and a native Tauri 2 desktop GUI layer [EV:doc:docs/adr/ADR-002-tauri-desktop-architecture.md#L4].
The entire codebase is partitioned across 12 focused Rust workspace crates and two application frontends [EV:tree@Cargo.toml].
All software components are compiled natively with full offline airgap enforcement [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L14].

## 2. Binary Artifact Distribution Inventory

The production build emits two primary application binaries accompanied by cryptographic checksum ledgers [EV:tree@Cargo.toml]:

### A. Headless Automation CLI (`mmi-studio-cli`)
- **Binary Executable**: `target/release/mmi-studio-cli` [EV:tree@apps/mmi-studio-cli/src/main.rs].
- **Purpose**: Provides headless batch automation for format inspection, hex viewing, entropy calculation, signature carving, recipe execution, conformance validation, build attestation, and media generation [EV:doc:apps/mmi-studio-cli/src/main.rs#L20].
- **Dependencies**: Statically linked native Rust binaries; zero runtime network dependencies [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L14].

### B. Desktop Workstation GUI (`mmi-studio-desktop`)
- **Binary Executable**: `apps/mmi-studio-desktop/src-tauri` / native desktop app [EV:doc:docs/adr/ADR-002-tauri-desktop-architecture.md#L24].
- **Frontend Assets**: Vite + React 19 + TypeScript single-page application [EV:tree@apps/mmi-studio-desktop/package.json].
- **IPC Handlers**: Direct native Rust command bindings (`mmi-core`, `mmi-formats`, `mmi-canvas`, `mmi-re-lab`) [EV:tree@apps/mmi-studio-desktop/src-tauri/src/ipc.rs].
- **Components Included**: `AssetBoard`, `ScreenCanvas` (800x480), `HexViewer` (binary RE lab), and `TypographyStudio` [EV:tree@apps/mmi-studio-desktop/src/App.tsx].

## 3. Software Bill of Materials (SBOM)

In accordance with automotive engineering supply-chain standards, two standard machine-readable SBOM manifests are provided in the release repository [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L4]:

1. **SPDX 2.3 JSON**: [`docs/deployment/sbom-spdx.json`](sbom-spdx.json) [EV:tree@docs/deployment/sbom-spdx.json].
   - Enumerates all 14 workspace crates, versions, declared licenses (MIT OR Apache-2.0), and package file paths [EV:tree@docs/deployment/sbom-spdx.json].
2. **CycloneDX 1.5 JSON**: [`docs/deployment/sbom-cyclonedx.json`](sbom-cyclonedx.json) [EV:tree@docs/deployment/sbom-cyclonedx.json].
   - Contains component dependency trees, scopes, and license classifications [EV:tree@docs/deployment/sbom-cyclonedx.json].

## 4. Release Build & Verification Procedure

Release compilation requires an airgapped build environment satisfying all offline constraints [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L14]:

```bash
# 1. Compile all workspace crates in release mode offline
cargo build --release --offline --workspace

# 2. Execute full automated test suite (all unit and integration tests)
cargo test --release --offline --workspace

# 3. Verify documentation evidence tag discipline
python3 scripts/check-evidence-tags.py
```

All 60 automated tests must exit with status code 0 prior to distribution authorization [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L370].

## 5. Mandatory Safety Verification Notice

Deployable media structures generated by this workstation must adhere to §14.9 safety guidelines [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L438].
The phrase "SAFE TO INSTALL" is permanently banned from all workstation tools, reports, and documentation [EV:doc:AUDI_MMI_STUDIO_AGENT_PROMPT.md#L438].
Every vehicle deployment must be preceded by a verified baseline emergency recovery bundle generated via `mmi-studio-cli stock-recovery` [EV:doc:docs/deployment/EMERGENCY_RECOVERY.md#L4].
